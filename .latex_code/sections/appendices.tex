\subsection{Reproducing our experiments}
Unpack \code{imdb_outputs.zip} into \code{imdb_outputs/}. Reuse these exports
rather than redownloading and resplitting. For the classical branch, install the
libraries used by the recorded environment and run \code{python model.py} from
the \code{ml/} directory. The script prints metrics; our saved result CSVs
remain the record of the reported run.

For GPU experiments, install \code{dl/requirements.txt} in an appropriate
environment, then run from the project root:
\begin{quote}\ttfamily\small
python dl/train\_lora.py --stage tune --dry\_run\\
python dl/train\_lora.py --stage tune\\
python dl/train\_lora.py --stage final
\end{quote}
The tuning stage never loads test data. The final stage selects the configuration
from the tuning table and protects existing final results from accidental
overwrite. The saved adapter requires the base model for inference.

\begin{samepage}
For evaluation and the demonstration, keep the package in
\pathcode{.eval_demo_package/}. Its scripts resolve data and outputs relative to
that folder. In a Python environment, install its requirements and prepare
the package's data and adapter path from the project root in PowerShell,
then enter it:
\begin{quote}\ttfamily\small
pip install -r .eval\_demo\_package/demo/requirements.txt\\
Expand-Archive imdb\_outputs.zip .eval\_demo\_package/imdb\_outputs\\
\$env:DL\_ADAPTER\_DIR = (Resolve-Path dl/checkpoints/distilbert\_lora).Path\\
cd .eval\_demo\_package
\end{quote}
\end{samepage}
Run the following commands from inside \pathcode{.eval_demo_package/}:
\begin{quote}\ttfamily\footnotesize
python eval/make\_ml\_preds.py\\
python eval/convert\_dl\_preds.py --dl-preds ../results/predictions/distilbert\_lora.csv\\
python eval/evaluate.py\\
python eval/tag\_errors.py\\
python eval/error\_analysis.py\\
python demo/check\_predictors.py --n 50\\
streamlit run demo/app.py --server.address localhost
\end{quote}
The first command retrains the four classical models on the fixed training
split, checks their metrics and saves model bundles and prediction files.
These generated files are not included in the submission. The conversion
command creates the DL prediction format used by evaluation and predictor checks.
The evaluation and error-analysis commands write their outputs under
\pathcode{.eval_demo_package/results/eval/}; our recorded tables and annotations are already included.
The tagging step downloads and caches the tokenizer before error analysis.
The package-specific data and adapter setup above accounts for its location
within the submission.
The app uses a configured adapter directory, a local model copy, or the committed
checkpoint in that order. It downloads and caches the base transformer on first
use. No public hosted demo URL is claimed.
